# \# Отчет по учебной практике: Система бронирования ресурсов

# 

# \*\*Проект:\*\* Backend-сервис для автоматизации бронирования (practice-backend-2026)

# 

# \## Описание проекта

# Данный сервис предназначен для управления бронированием помещений и ресурсов. В ходе выполнения 1-го и 4-го этапов практики были решены задачи по обеспечению безопасности и корректности бизнес-логики.

# 

# \## Реализованный функционал

# 

# \### 1. Безопасность и Auth-контур (Этап 1)

# Согласно заданию, из системы был исключен метод передачи `user\_id` через параметры запроса. 

# \- \*\*JWT (JSON Web Token):\*\* Реализована авторизация на базе OAuth2. При входе пользователь получает токен, который используется для всех операций.

# \- \*\*Dependency Injection:\*\* Внедрена зависимость `get\_current\_user`, которая автоматически извлекает объект пользователя из токена. Это исключает возможность подмены ID.

# 

# \### 2. Модель интервального бронирования (Этап 4)

# \- \*\*Time Intervals:\*\* Базовая модель `Booking` переработана. Вместо одной отметки времени используются `start\_time` и `end\_time` (тип данных `DateTime`).

# \- \*\*Алгоритм Overlap Validation:\*\* Реализована проверка пересечений на уровне SQLAlchemy. Логика запроса гарантирует, что один и тот же ресурс не будет забронирован дважды на одно и то же время.

# 

# \## Технические подробности

# \- \*\*FastAPI:\*\* Использован для создания асинхронного API.

# \- \*\*Docker Compose:\*\* Настроена оркестрация контейнеров (сервис + база данных) для быстрой развертываемости.

# \- \*\*Автодокументация:\*\* Подключен Swagger UI (доступен по /docs).
